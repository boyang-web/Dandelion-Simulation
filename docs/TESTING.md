## 1. 资源约束（为什么测试长得不一样）

之前的验证使用 1440×900、9000 簇草、1920×1080 快照，软件渲染会长时间占满 CPU。
当前测试夹具改为**低资源模式**：

| 项 | 取值 |
|---|---|
| 视口 | 760 × 480 |
| 画质 | `?quality=low`（5000 簇草） |
| 后期 | `?post=0` |
| 进程 | `--renderer-process-limit=1`，`nice 15`（最低优先级） |
| 加载 | 单次页面加载，硬性时间上限（默认 55 s） |
| 回读 | 不使用 1920×1080 快照 / 视频编码 |

```bash

LIGHT_ONLY=plant python3 tools/e2e/test_light.py  # 只跑某一段
```

完整套件（多页面、全尺寸、截图）仍保留在 `tools/e2e/test_experience.py`，

## 3. 已知未覆盖

1. **软件渲染的长时稳定性**：GPU 进程在 40–60 s 后失效，长套件会被中断；真实 GPU 不会。
2. **1920×1080 快照与 5 s 录制**：在低资源模式中刻意跳过（内存与编码耗时），只在全尺寸运行中验证过。
3. **移动端松手减速**的断言阈值最后调整过一次，未再单独复跑；摇杆推动与手柄跟随已通过。

## 4. 这次测试覆盖了什么

- 测的是**接线**：组件事件 → engine API → store → 模板更新，以及三条关键流程（种植、解锁、胶片）。
- 不测**视觉质量**：软件渲染与真实 GPU 的画面不同；画面验收请看演示文稿中的示意图或你在本机打开页面。
- 不测**性能数字**：SwiftShader 的帧率没有参考价值；性能结论来自代码路径（实例化、LOD、帧循环不经过 Vue）。
