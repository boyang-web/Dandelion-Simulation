# 等风来 · Dandelion

一朵由代码生成的蒲公英，长在一片安静的草原上。  
滑动鼠标或手指，让风从蒲公英上经过——种子飞起、飘远，然后花头会慢慢把种子长回来。

整个场景没有外部贴图或模型：蒲公英、种子绒、草地、山脊、花粉都由代码绘制。

---

## 运行

需要通过 HTTP 打开（ES Modules 不能直接用 `file://` 运行）：

```bash
cd dandelion
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/
```

Three.js 已放在 `vendor/` 中，离线也能运行。  
建议使用较新的 Chrome / Safari / Edge，并开启 WebGL 硬件加速。

## 怎么玩

- **电脑**：不必按住鼠标，直接滑过蒲公英即可。滑动越快，风越大。
- **手机**：手指按住并滑过蒲公英。
- 风只作用在**光标（手指）经过的区域**，不会同时吹动整片草地。鼠标就是那个"在草地里掠过的物体"。
- 已经飞出去的种子也有惯性：离开风区后它们会继续飘，只是慢慢减速；下一次手指经过附近，还能再次改变它们的轨迹。
- 花头会以固定节奏重新长种子，约 40–60 秒从全秃长满。
- **调整时间**：长按天空中的太阳或月亮约 **0.1 秒**，然后**沿着天空弧线**拖动。太阳落到西边地平线后不会被卡住，可以继续沿弧线滑到地表以下，时间会继续推进，月亮从东边升起；地下时当前光体只保留一个很淡的影子手柄，松手后彻底隐藏。也可以松手后直接长按月亮继续拨动。没有显式按钮，光体本身就是手柄。

## 它是怎么工作的

### 局部风场（`js/wind.js`）

1. 记录指针的屏幕路径，每隔很短的时间把 `上一个点 → 当前点` 压入一条很短的 trail。
2. 每条 trail 保存**当时的空气速度向量**，而不是只保存一个全局方向。
3. 某个点查询风时，取附近 trail 段和自己当前位置中影响最大的一段，乘以平滑的径向衰减（`radiusPx`）。
4. trail 只存在 0.45 秒，所以风吹过之后会留下短暂的余流，但不会变成全屏风。
5. 屏幕速度（px/s）经摄像机左右/上下轴映射成世界空间的风向；速度越快，`strength` 越大。

草、蒲公英花头、每一颗飞行中的种子、花粉，都通过同一个局部风场取各自位置的空气速度。

### 种子的惯性（`js/dandelion.js`）

飞行种子每帧只做一件事：向**自己所在位置**的局部空气速度靠拢：

```js
response = 0.34 + 1.55 * exposure;   // 在风区里响应快，风区外响应很慢
vel += (localAir - vel) * (1 - exp(-response * dt));
```

- `exposure` 是种子位置上的局部风速占最大风速的比例。
- 离开风区时 `response` 只有 0.34/s，种子会保留大部分动量，缓慢衰减。
- 还有轻微重力、空气摆动和飘落姿态，风只是改变它，而不是直接“摆到”目标位置。

### 被吹散

蒲公英花头只检查**花头位置**上的局部风，所以：

- 从蒲公英上滑过：花头抖动，种子按当地风向被扯下；
- 在草地别处滑动：只有附近的草和花粉动，花头完全不受影响。

种子脱离时会继承一部分当地风速，并获得一个沿径向的小踢腿；之后继续受局部风影响。

- 每颗离体的种子会在脱离瞬间锁定一个**约 ±10% 的个体尺寸**，并在 0.45 秒内从花头上的原始大小平滑过渡到该尺寸；这样同一阵风里的种子不再像同一张剪贴画复制出来的，前后层次更明显。
- **主茎会随风轻摆**：静风时也有一条极慢的呼吸式晃动，花头处有风时摆幅略增；花托、绒球和所有仍在花头上的种子共用同一个根部支点，花头移动时种子一起移动，已经飞出的种子不受影响；黑影贴地，不会跟着茎离开地面。

### 时间与光

太阳和月亮是同一段天空弧线上的两个光体，永远位于弧线的对侧，不额外渲染按钮：

- **时间会自动流逝**：整条日月弧线约 **120 秒**走完一圈（白天约 60 秒、夜晚约 60 秒）；拖动日月时暂停，松手后停 2.5 秒再继续，避免刚调好的光立刻跑掉；开发面板底部可以手动「暂停时间 / 继续时间」，`?still=` 静态截图模式不推进；
- 天体是**柔焦光晕**，没有硬边圆盘；白天/夜晚由太阳高度决定，接近地平线时自动过渡到金色黄昏/黎明；
- 指针在太阳或月亮上按住约 0.1 秒进入时间模式，之后**沿弧线拖动**；时间由指针绕弧线圆心的角度决定，不做上下直线映射；
- **拖过地平线不会被截断**：当前光体可以继续滑到弧线地下，时间继续前进，另一侧的光体从对面升起；地下只显示低透明度的影子手柄，松手后隐藏；
- `currentTime` 的 0 是日出、0.25 正午、0.5 日落、0.75 午夜、1 回到日出；
- 日落时太阳沉到右侧地平线，月亮同时从左侧地平线升起；继续长按月亮沿弧线向上，可以进入深夜；
- 悬停或拖动时会出现一条极淡的虚线弧，拖动时连地平线以下的半圈也会显示，作为轨道提示；
- 天体位置、太阳/月亮光晕、CSS 夜色/金色光层、星空、三盏灯、草地与地面的 `<uniform>`、蒲公英绒毛颜色、阴影强度和界面文字颜色都会同步更新；
- 长按/拖动事件会阻止冒泡，不会同时触发局部风；
- 支持键盘，焦点在任一天体上时 `←` / `→` 沿时间轴前后拨动，`Home` / `End` 跳到日出 / 午夜。

### 复生

每颗种子脱离后会释放它在花头上的槽位。花头约每 **0.16–0.28 秒**在空闲槽位长出一颗新种子，从花托向外舒展张开（缩放 + 径向位移），整朵约 40–60 秒长满。

### 草原与光（`js/world.js`）

- 三层程序化山脊，带底部雾霭和朝向太阳一侧的微暖光；
- **210m × 210m 高度场地形**：向远处缓慢抬升，叠加三层低频起伏，不再是整块平地；蒲公英脚下保留半径约 2.35m 的平整空地，花和草从这个空地边缘开始生长；
- **5 种草资产、共 9000 簇**（桌面）/ 5000 簇（coarse），**4 种花、12 个花片区共约 432 朵**；每株都按 `terrainHeight()` 落地；
- 4 个近景花片区放在镜头前，并用低草视廊 + 近景放大（1.45–1.60×）避免被高草完全挡住；
- 5 种草按相同权重抽取，并启用每种 3 个种子变体，合计 27 个 `InstancedMesh`；近景草向镜头前额外加权，密度更高；
- 夜晚会缓慢渐入 **110 只萤火虫**：柔黄色、深幅呼吸（亮度约 4%–100%）；独立渲染在夜景遮罩上方的透明层里，所以不会被夜色压暗；受同一局部风场影响，同时保留自然漂移与回弹；
- 花片区里的草会减密并压低，花头能从草面里露出来；远景草簇和花随距离进入雾霭；
- 每簇草的**根部固定在实例位置**，风只让上段按圆弧弯曲，不会拖动整片草地；
- 草/花共用同一个局部风场：比种子更小的半径、会轻微滞后跟随指针的锚点、经过平滑滤波的强度与方向；
- 草的局部风有额外阻尼：方向按角度低通、强度和扫过区域的前后端都做慢速滤波；只有真正快速反向才触发“一致性闸门”，把受力压到约 15%，随后较快恢复；普通单向滑动仍接近满幅；种子和蒲公英保持原来的响应；
- 花朵的所有花瓣、花心、叶片与茎共用同一弯曲相位，整朵花一起摆；
- 地面有慢慢漂移的云影（`uTime`）和暖色夕照，山脊有日光边；
- 蒲公英种子有迎光面/背光面的细微暖冷差异；
- 花粉点随局部气流漂动，并贴着地形高度；
- 镜头不再跟随鼠标产生视差（只保留极慢的呼吸），所以滑动鼠标时地面保持固定；
- 天光、多层软云、太阳/月亮的柔焦光晕来自 CSS，WebGL 画布使用透明背景叠加；
- 光线后期见 D 组：泛光、空气散射、草叶透光、根部 AO 与同色雾霭。

### B · 单株资产库（`vegetation.html`）

这是正式草地装配前的资产阶段，主场景本身还没有换草：

- 5 种草：银羽草、草甸草、低簇草、干芒草、宽叶草；
- 4 种花：小白菊、小毛茛、勿忘我、蓝紫穗；
- 每种 3 个种子变体；`js/vegetation.js` 中每个资产都是 **1 个合并 `BufferGeometry`**，带 `position / color / normal / aBend / aPhase / aFlutter`，下一步可以直接喂给 `InstancedMesh`；
- `createVegetationMaterial()` 用 `MeshStandardMaterial + onBeforeCompile` 做固定根部的风弯曲，保留顶点色、主光和阴影；
- 资产页可以单独查看每一株、切换 3 个变体、重新播种、调风、拖动旋转与滚轮缩放；
- 预览：`http://localhost:8124/vegetation.html`（也可以直接打开 `vegetation.html`）。

### C · 山坡草地装配（主场景）

- 主场景的平地已经换成了 210m 高度场地形，向远处缓缓抬升，并叠加更大振幅的低频起伏；
- 用 B 组的 9 个资产铺草与花：9000 簇草、约 432 朵花（coarse 设备 5000 簇 / 约 311 朵）；花朵集中在 12 个 patch 里，4 个花种各 3 片；
- 近景 4 个花片区带低草视廊，近景花朵放大 1.45–1.60×；
- 草和花的根点全部重新采样地形高度，因此会顺着坡面生长；近景草额外加密，远景仍保留雾霭；
- 每个草簇/花朵仍使用局部风场，根部固定，任何风都不会把植株整体拖走；
- 夜晚 110 只柔黄色萤火虫缓慢渐入，缓慢呼吸；独立叠加在夜景遮罩上方，受局部风推动，同时有自然漂移与回弹；
- 27 个 InstancedMesh（9 资产 × 3 种子变体），桌面约 2.7M 三角形；coarse 设备自动降到 5000 簇。

### 手机竖屏 / 横屏

- **竖屏**：`fov 33`、机位后移到 `z = 11.7`，让蒲公英在窄屏里保持宽度；
- **横屏**：`pointer: coarse` 且视口高度 `≤ 560` 时切换到 `fov 35`、`z = 9.9`，视线稍微下压，
  让花头、前景草和山脊线同时落在短屏里；
- **日月弧线**：横屏下弧线被压平（`cy = 0.56H`、`ry = 0.30H`、`rx = 0.36W`），
  正午太阳不会钻到屏幕顶边/刘海下面，日出日落仍在左右地平线上；
- **界面**：横屏下标题缩到 24px、提示条下移并缩小、隐藏 WIND 条、天体控件缩到 136px，
  并给额头和左右刘海留出 `env(safe-area-inset-*)` 安全区；
- 开发控制台在横屏下宽度限制为 340px，高度不超过视口，可滚动调参。

### D · 光线质感（`js/post.js` + 着色器）

这一轮不再改构图，只改“光怎么落在这片草地上”：

- **泛光 + 高光滚降**：场景先渲进线性 HDR 缓冲，再把超过阈值的亮部（蒲公英绒球、逆光草尖、加色光晕）抽出、两级模糊后加回画面；高光只压缩最后一段，避免糊成一片；
- **空气透视**：地形、草、山脊的雾霭颜色随一天变化（黎明冷蓝 → 黄昏暖橙 → 深夜墨蓝），不再是白天那张奶油色雾霭；
- **太阳方向散射**：后处理按视线与太阳夹角做单次散射，朝太阳看时整片空气会轻微发亮，和 CSS 天空光晕连在一起；
- **草叶透光**：逆光时草尖按 `dot(-V, L)` 透出暖色，叶片上再加一层很薄的高光；这是黄昏草地最明显的真实感来源；
- **根部 AO**：草簇靠近地面的部分压暗，花片区脚下的地面也有静态接触 AO，植株不再像“贴”在地上；
- **同步云影**：地面和草共用同一组缓慢漂移的噪声云影，草面与地面会一起暗、一起亮；
- **色调分级**：轻微提升饱和度，冷暗部 + 暖高光的分色，配合 `?time=` 的日/月切换。

泛光、曝光、散射、饱和度、远景雾化、云影强度、草叶透光、根部阴影都在控制台里，可实时调完再固化。

### 远景 · 云 / 鸟 / 山

- **雾化统一**：地面、草和山脊共用一条指数衰减的雾化曲线（`aerialFog`），草的雾化不再比地面提前结束；雾色会随太阳方向变暖，并叠一层缓慢噪声，不再是一块死板的奶油色；
- **云**：主场景也换成了真正的 3D 云层（远/中/近三档平面），程序化 fBm 纹理，云顶受光、云底发灰，随距离和夜色一起压暗；山脊会正常遮挡云脚，日落时云底转暖。原先铺在 CSS 里的八团柔云和地平线云带已移除；
- **鸟**：远景会偶尔飞过一小群鸟（主场景 18–42 秒一次），7 只一组，真实 3D 剪影、在顶点着色器里振翅；飞过山脊时会自然被山挡住，天黑了就不出现；
- **山**：三层山脊重新抬到地形天际线之上（之前它们其实被抬升的地形挡住了），新增一层更远的山；山脊线加了高频起伏，山腰有灌木/褶皱色斑，山脊受光会随黄昏变暖；
- 开发面板的“召唤鸟群”可以立刻放一群鸟，不用等。

### 远景预览（`distant.html`）

专门用来打磨远景的独立页面，不加载蒲公英、草地、花和萤火虫：

- 只保留太阳/月亮弧线、云层、地表天际线、三层山脊和鸟群；
- **3D 云层**：程序化 fBm 云纹理，按远/中/近三档距离摆放，云顶受光、云底发灰，沿各自速度横向漂移；真实平面因此会被山脊遮挡，远层更淡更慢；
- **山脊层次**：近山压暗、中山转灰绿、远山偏蓝且整体更雾；山脚雾更厚、山脊也保留一层空气感，三层轮廓和高度差都拉开了；
- **树线**：近山脚加了一条由重叠树冠组成的暗色树线，打破纯山谷轮廓；
- **鸟群景深**：一群鸟从近处斜着飞向远处，透视 + 体型渐缩 + 透明度渐降，飞过山脊时会被挡住；
- **更高的山**：远山 `14 + 8.5`、中山 `8 + 5`、近山 `3.6 + 3.4`，峰谷落差和层间高度差都加大；
- **竖屏适配**：远景相机在竖屏下使用更广的视场、更远的机位；控制台在 ≤560px 时占满屏宽；
- 相机比主场景略高、略远，地平线落在画面中间，方便同时看三层山脊；
- 共用同一套 `Sky`、雾化、后处理和开发控制台；控制台只显示 **画面 / 远景** 两组，参数单独存到 `dandelion.dev.distant.v2`，不会和主场景互相覆盖；
- 支持 `?time=`、`?still=`、`?clean`、`?debug=1`、`?post=0`，也可以直接双击打开（`file://` 使用 `js/bundle-distant.js`）。

### 梧桐树资产 · 缺陷与修复记录（2026-11-20）

`js/tree-assets.js` 曾把整棵树渲染成"从地面一点放射出的直棍扫把"。排查确认是几何索引 bug，而非造型参数问题；同批还修掉了若干材质/结构缺陷。记录如下，便于回归：

- **枝干索引连到原点（畸形根因）**：`addTube()` 拼三角形时读 `rings[i]`，但 `rings[i] = ringStart` 的赋值写在索引块之后，读到的永远是 `undefined`；`undefined + s` 得 `NaN`，索引上传 GPU 时 `NaN` 变 `0`，于是每根枝干有一半三角形连到全几何第 0 号顶点（树干基部环首点，原点附近），整棵树被拉成放射扇形。叶片索引另写、未受影响，所以叶子仍飘在梢上。修复：改用当前环的 `ringStart`（现 `js/tree-assets.js:229`）。
- **双重 gamma**：贴图已设 `SRGBColorSpace`（采样时硬件解码到线性），片元着色器又 `pow(tex.rgb, 2.2)` 再压一次，叶片反照率暗约两个数量级、几乎全黑，画面颜色被背光项主导（正面看发土黄）。修复：去掉二次 gamma（`js/tree-assets.js:583`）。
- **背光项不看叶面法线**：透射只按视线×太阳方向计算，迎光面也发白。修复：乘 `max(dot(-n, L), 0.0)`，只让真正背光的叶透亮（`js/tree-assets.js:595`）。
- **枝干管口无封盖**： tube 两端开口，看到管内壁形成黑洞（树干上的黑椭圆）。修复：补端盖扇面（`js/tree-assets.js:244`）。
- **风吹时叶脱离枝**：叶片 `aBend` 恒为 1，枝干为 `(y/6.4)^1.1`，摆幅不一致。修复：叶片改用同一高度公式（`js/tree-assets.js:275`）。
- **叶脉画出叶廓外**：叶脉线超出叶片轮廓呈星芒杂线。修复：`Path2D + clip` 限制在叶内，裂片加宽更接近五裂掌状叶（`js/tree-assets.js:74`）。
- **树冠稀疏呈十字、高度超标**：递归仅 2 层、子枝缺水平方位分叉，顶视呈稀疏十字；实际高 7.2 m 与档案标注不符。修复：递归 2→3 层、加水平方位分叉、外梢微垂成圆冠，并把高度归一化到 6.1 / 6.4 / 5.8 m（`js/tree-assets.js:488`）。

修复后已用无头 Chrome 验证模块模式、`file://` bundle 模式、正/侧/顶/特写四视图与"全部陈列"，均无 JS 报错；并跑 `tools/build-classic-bundle.py` 重建经典包，使离线打开同步生效。

**茂密化重做（同日二次迭代）**：上述修复后树冠仍偏稀疏，按"先粗再细、注重整体效果"重做。第一版用 5 个椭球拼包络，虽茂密但剪影呈"西兰花"球块、且冠大干细头重脚轻；遂改为**单一连续包络**：`crownEnvelope()` 以椭球为基、叠 3 组低频谐波做有机起伏，冠底压平并加一侧垂挂 + 两处缺刻（露出主枝分叉、打破棒棒糖感），顶部略收；`CROWN_PRESETS` 按变体调干高/冠宽。主干加高加粗（约 3.4 m、基径 0.27）并带轻微倾斜，主枝自 0.46–0.88 干高斜出、先横展再入冠；`fillCrown()` 按体积密度（约 105 卡/m³）散布叶片卡、62% 外壳偏置。叶片法线全球随机（原先偏朝上、侧视几乎 edge-on，是显稀疏的主因之一）。单株约 1.85 万顶点 / 1.2 万三角，高 6.1 m、冠幅约 5.0 m，正/侧/顶视剪影为单一有机轮廓且实心茂密。

### DEV · 交互参数控制台

**用户启动和开发者启动已经分离**：`index.html` 是无控制台的生产入口，不会创建
DEV 按钮、不会读取浏览器里保存的调参值；开发者用 `dev.html`，或
`index.html?dev=1` 启动。

开发阶段直接在页面上调参，不用再反复改代码：

- 开发者入口固定为 `dev.html`（会跳到 `index.html?dev=1`）；面板按**画面效果**
  分成 **画面 / 远景 / 草地与风 / 蒲公英 / 萤火虫** 五组，共 24 个实时滑杆；
  手势平滑、阈值、低通等内部参数不再暴露，保持默认值；
- 修改立即写入运行时对象，下一帧生效；
- 自动保存到 `localStorage`（`dandelion.dev.v2`），并在“最近修改”里记录时间、参数、值；
- “复制参数”会把当前全部参数和场景规模复制到剪贴板，直接发给我，我固化成源码默认值；
- “重置”恢复代码里的初始值；
- 面板和滑杆都带 `data-no-wind`，调参时不会误触草地风场；
- 当前固化的生产默认值见 [`docs/DEFAULTS.md`](./docs/DEFAULTS.md)。

## 直接双击打开 / 发布

`index.html` 现在可以直接在 Finder 里双击打开，不需要本地服务器。

- `file://`：自动切换到 `vendor/three.global.js + js/bundle.js` 经典脚本包，绕过浏览器对 `file://` ES module 的拦截；
- **用户启动无控制台**；调试用 `dev.html` 或 `index.html?dev=1`；

```bash
python3 tools/build-classic-bundle.py
```

大多数手感参数在文件顶部或构造处：

  - `this.regrowTimer = 0.16 + random * 0.12`：复生节奏

- `js/world.js`
  - 草地数量、山脊高度、颜色都在文件内的生成函数里。

## 调试 / 截图参数

- `?debug`：左下角显示 fps、花头数、飞行数、局部花头风速、种子平均速度。
- `?auto`：自动演示，每隔几秒让一个不可见的“手”扫过蒲公英。
- `?still=3.5`：同步模拟 3.5 秒后只渲染一帧（给无头截图用）。
- `?still=3&gust=1.5`：在 1.5 秒时模拟一次扫过蒲公英的风。
- `?still=3&gust=1.5&gustx=0.85`：把手放到屏幕右侧 85% 处挥动，用来验证“远处不会吹动花头”。
- `?clean`：隐藏界面文字，适合截图。
- `?post=0`：关掉光线后期（泛光/散射/调色），用于对比原始直出画面。
- `?time=0` / `?time=0.25` / `?time=0.5` / `?time=0.75`：日出 / 正午 / 日落月升 / 午夜，方便查看时间配色。

例如：

```bash
# 局部风确实吹动花头
http://localhost:8000/?still=3&gust=1.5&debug=1

# 同强度风，但在花头远处 —— 花头保持 220 颗
http://localhost:8000/?still=3&gust=1.5&gustx=0.85&debug=1
```

## 几个设计取舍

- **屏幕空间风场而不是 3D 风场**：鼠标本来就在屏幕上，用屏幕路径定义局部风最直观；每个物体投影到屏幕再查询，代价低且不受景深影响。
- **trail 而不是只看当前点**：快速滑动可能一帧跨过花头。保留 0.45 秒的路径余流，保证“手掠过去”这件事真的发生，而不是靠运气踩中某一帧。
- **每颗种子独立查询风**：不共享一个全局力；这样飞行中的种子能被新的手指风单独推动，也自然支持“局部风”的要求。
- **轻量自写物理**：用指数趋近代替完整流体/刚体，稳定、可调，手机上也能跑。
- **固定根部的草叶**：风摆改成围绕根部旋转的圆弧，长度基本守恒；固定镜头取消指针视差，避免“整片地面被拖动/拉伸”的错觉。
